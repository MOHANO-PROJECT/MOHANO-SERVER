신고·자동 이용 제한
===================

상태: 사용자 신고와 최근 24시간 기준 자동 제한 API를 구현했다. 운영자 화면과 수동 처리 API는 아직 만들지 않았다.

변경 목적
---------
신고를 무제한으로 남발하는 것을 막으면서, 여러 이용자에게 반복 신고된 계정을 빠르게 보호 조치한다.
제한된 계정도 로그인과 프로필·설정 확인은 가능해야 하지만, 다른 이용자와 새로 상호작용하면 안 된다.

확정한 결정
-----------
- 신고자는 최근 24시간 안에 최대 5건의 신고만 제출할 수 있다.
- 같은 신고자가 같은 대상을 최근 24시간에 다시 신고하면 중복 신고로 거절한다.
- 서로 다른 신고자 3명 이상이 한 대상에 대해 최근 24시간 안에 신고하면, 대상 계정을 자동으로 24시간 제한한다.
- 자동 제한 중에는 매칭 조건/후보, 채팅 목록·읽기·전송, 통화 요청·수락·신호·종료, availability presence 갱신을
  서버에서 `403 account_restricted`로 막는다. 로그인, 로그아웃, 계정 삭제, 프로필과 안전 상태 조회는 유지한다.
- 자동 제한 시 진행 중인 pending 통화 요청은 취소하고 `connecting` 상태의 통화 세션은 종료한다.
- 제한된 사용자는 후보 쿼리와 통화 가능 대상에서도 제외한다.
- 신고 사유는 괴롭힘, 사칭, 성적 콘텐츠, 차별/혐오, 사기/스팸, 기타 중 하나이며, 선택적으로 1,000자 이하의
  상황 설명을 남길 수 있다.

API·데이터 요구사항
-------------------
- `POST /v1/reports`: `reported_user_id`, `reason`, 선택 `evidence`를 제출한다. 성공 시 신고 ID, 시각,
  최근 24시간에 남은 신고 가능 횟수를 반환한다.
- 통화 요청·세션 응답에는 신고 진입점에 필요한 상대 사용자 ID를 `counterpart_id`·`peer_id`로 함께 반환한다.
- `GET /v1/me/safety-status`: 로그인 가능한 제한 계정이 앱에서 안내를 표시할 수 있도록 제한 여부와 종료 시각을 반환한다.
- `users.restricted_until`은 현재 자동 제한 종료 시각을 보관한다.
- `user_reports`는 신고자, 대상, 사유, 증거 설명, 처리 상태, 시각을 보존한다.
- `safety_actions`는 대상, 자동 조치 종류/사유, 판정에 사용한 기간과 신고자 수, 실행 시각, 제한 종료 시각을 보존한다.
- 신고 생성과 3인 판정은 대상/신고자 사용자 행을 정렬해 잠근 하나의 DB transaction 안에서 처리한다.

다음 작업 또는 미결정 사항
--------------------------

  자동 정지 이력을 검색·열람할 수 있어야 한다.
- 운영자 수동 조치(사진/프로필/메시지 숨김, 경고, 제한 연장·해제, 계정 정지)와 그 조치자·사유·시각의
  감사 이력을 정의한다. 운영자 권한 모델, 신고자 개인정보 접근 최소화, 증거 보관·삭제 기간은 출시 전 확정한다.
- 차단 기능, 신고 대상별 컨텍스트 스냅샷(사진 object key, 프로필 버전, 메시지 ID), 이의 제기와 사용자 처리 상태
  알림은 별도 계약으로 추가한다.
