광고·구독 수익화 설계
======================

목적
----
무료 이용자는 자연스러운 전환 지점에서 광고를 보고, 광고 없는 지속 이용을 원하는 이용자에게 월 구독을
제공한다. 통화 연결은 요금제와 관계없이 session당 30분으로 제한한다. 광고·결제 상태는 클라이언트 화면만으로 판단하지 않고 서버의
entitlement와 이용 이력으로 일관되게 적용한다.

확정한 상품 정책
----------------
- 무료·Plus 이용자 모두 하나의 연결 session당 최대 30분이다. 종료 1분 전과 종료 시점에 양쪽에 안내한다.
- 후보 10명 배치를 모두 확인한 무료 이용자가 `다시 찾기`로 다음 배치를 요청할 때 전면광고를 1회
  표시한다. 그 배치에서 통화 신청·수락이 한 번도 없었더라도 다음 배치에는 동일하게 적용한다.
- 무료 이용자는 상대별로 그날의 첫 메시지를 보내기 전에 전면광고를 1회 본다. 날짜가 바뀌면 같은
  상대와의 첫 메시지에도 다시 광고를 적용한다.
- 첫 광고 뒤에는 같은 상대에게 보낸 무료 메시지 10건마다 다음 광고 gate를 적용한다. 앱은 작성 영역에
  `오늘 무료 메시지 n/10` 또는 남은 건수를 표시한다. 10번째 메시지가 서버에 저장된 뒤 다음 발신 전
  광고를 보여 주므로, 메시지를 작성하는 도중에는 광고가 갑자기 나타나지 않는다.
- 월 780엔 자동 갱신 구독자는 위 광고를 보지 않으며, 통화 횟수·채팅 사용량을 상품상 무제한으로 이용한다.
- "무제한"은 요금제 제한이 없다는 의미다. 신고·차단·계정 제한, 서비스 장애 대응, 향후 별도 안전 상한은
  계속 적용할 수 있다.
- 강제 외부 광고 위치는 후보 10명 배치 전환과 상대별 메시지 광고 gate로 제한한다. 앱 기동·온보딩,
  프로필 편집·사진 업로드, 채팅 목록, 통화 수신/연결/종료, 신고/차단/설정에는 외부 광고를 표시하지 않는다.
- 당일 두 번째 광고 gate부터는 광고 아래 또는 광고 종료 뒤에 `광고 없이 계속하기 — 월 780엔`이라는
  자체 구독 안내를 작게 보여 준다. 광고를 닫거나 구매하지 않아도 광고 시청 뒤의 원래 흐름은 계속된다.

현재 구현 범위
--------------
- call session은 서버 기준 최대 30분으로 만료되며, 앱의 통화 화면은 음성 연결 직후 `30:00`부터
  남은 시간을 표시하고 `00:00`에 로컬 WebRTC 연결도 종료한다.
- entitlement 저장 구조와 무료/Plus 판정은 구현됐지만, 실제 스토어 구매 검증과 광고 SDK는 아직 연결하지 않았다.
- `subscription_entitlements`, `discovery_daily_usages`, `chat_daily_usages`, `ad_gate_events` migration을
  추가했다. 서버는 사용자의 IANA timezone 기준으로 첫 후보 배치를 무료로 제공하고, 이후 배치와
  상대별 당일 첫 메시지·10건 단위 메시지의 gate 상태를 판단한다.
- 후보 API와 메시지 저장 API는 gate가 해제되지 않으면 `409 advertising_gate_required`를 반환한다.
  후보/채팅 gate 완료 API는 개발 미리보기용으로만 존재하며, 실제 출시에서는 광고 SDK의 표시 완료
  callback 뒤에만 호출한다. 광고 식별자·클릭 URL은 저장하지 않는다.

광고 표시 원칙
--------------
- 후보 배치가 끝나고 다음 배치를 시작하기 직전, 새 채팅을 시작하기 직전처럼 사용자가 예상할 수 있는
  전환 지점에서만 전면광고를 표시한다.
- 통화 수신·통화 연결·통화 중·통화 종료 직후, 온보딩, 프로필 저장, 신고/차단 같은 안전 흐름에는
  광고를 표시하지 않는다.
- 광고는 미리 로드하고, 이용자가 명시적으로 다음 단계 버튼을 누른 뒤 표시한다. 늦게 도착한 광고가
  다른 화면 위에 갑자기 뜨지 않게 한다.
- 광고를 열기 전과 광고를 닫은 뒤에는 자체 구독 안내와 외부 광고를 시각적으로 분리한다. 구독 안내는
  광고처럼 보이게 하거나 오인 클릭을 유도하지 않는다.
- 광고 재고 없음, 네트워크 실패, SDK 오류일 때는 이용자를 막지 않고 해당 단계로 진행시킨다. 광고를
  보지 못한 일을 광고 시청으로 기록하지 않는다. 대신 해당 gate를 이번에는 면제했다는 서버 이력을 남겨
  재시도할 때 같은 광고가 반복해서 뜨지 않게 한다.
- 광고 식별자, 개인 맞춤 광고 동의, EEA/영국/스위스의 CMP·철회 흐름, 15세 이용자에 대한
  연령 제한 광고 처리는 실제 AdMob/광고 SDK 도입 시 공식 SDK 정책에 맞춰 별도 구현한다.

구독 entitlement 원칙
--------------------
- Android는 Google Play Billing, iOS는 StoreKit 자동 갱신 구독을 사용한다. 앱은 구매 UI만 담당하고,
  서버가 스토어 영수증/거래 상태를 검증해 entitlement를 발급한다.
- entitlement에는 사용자 ID, 스토어, product ID, 원거래 식별자, 현재 상태, 시작/만료 시각,
  취소·환불·유예·복원 이력을 보관한다. 원거래 식별자는 로그에 그대로 남기지 않는다.
- 하나의 MOHANO 계정으로 로그인한 여러 기기에서 같은 entitlement를 적용한다.
- 설정 화면에 현재 플랜, 다음 갱신/만료 예정일, 구매 복원, Google Play/App Store 구독 관리 링크를
  제공한다.
- 구독이 취소되어도 이미 결제한 기간이 끝날 때까지 혜택을 유지한다. 환불·결제 실패·스토어 알림은
  서버가 다시 검증해 상태를 갱신한다.

데이터·API 요구사항
-------------------
- `subscriptions` 또는 `subscription_entitlements`: 스토어 검증 뒤의 현재 entitlement와 이력.
- `ad_gates`: 사용자별 후보 배치 완료/다음 배치 광고, 그리고 `발신자 × 상대 사용자 × 사용자의
  현지 날짜`별 채팅 첫 광고·10건 단위 광고 상태를 기록한다. 광고 SDK callback만 신뢰하지 말고,
  서버가 다음 후보·채팅 쓰기 권한을 판단할 때 사용한다.
- 당일 경계는 기기 시간이 아니라 서버에 저장된 프로필 IANA timezone으로 계산한다. timezone이 없는
  기존 계정은 UTC를 임시 기준으로 쓰고, 앱이 다음 foreground 동기화에서 값을 갱신한다.
- 후보 API는 현재 배치 식별자와 배치 완료 상태를 반환하거나, 별도 광고 gate 확인/완료 API를 제공한다.
- 채팅 API는 현재 발신자 기준의 당일 광고 gate 상태, 무료 메시지 사용량, 다음 광고까지 남은 수를
  반환한다. 수신 메시지·통화 연결 같은 시스템 메시지·실패/중복 전송은 카운트하지 않는다.
- 통화 수락으로 자동 생성된 채팅방은 열람만으로 광고를 요구하지 않는다. 해당 사용자가 그 방에서
  그날 처음으로 메시지를 발신할 때 gate를 적용한다.
- 통화 session에는 요금제와 무관한 종료 예정 시각을 저장하고, 서버가 30분에 양쪽 session을 종료한다.
- 광고 노출은 개인정보를 최소화한 집계 이벤트로만 측정하고, 원본 광고 식별자·클릭 URL은 저장하지 않는다.

출시 전 미결정 사항
--------------------
- 780엔이 세금 포함 가격인지, 일본 외 통화/지역 가격과 무료 체험·첫 달 할인 여부.
- 광고가 준비되지 않았을 때 무료 진행을 허용하는 fallback의 분석·재시도 기준.
- 구독자의 기술적 통화 안전 상한(예: 장시간 연결 정리)과 통화 30분 종료 전 안내 문구.
- App Store/Google Play 상품 ID, 테스트 계정, 서버 검증 키·스토어 서버 알림 구성.
- 구독 안내 노출 기준(현재안: 당일 두 번째 광고 gate부터), 문구·통화·지역 가격·무료 체험 여부와
  광고 종료 뒤 표시 위치.
- 광고 SDK의 인증된 CMP, 맞춤형 광고 동의 철회, Data Safety/Privacy Nutrition Label, 국가별
  미성년자·환불·전자상거래 고지 검토.
- Google Play Billing/App Store StoreKit 검증을 연결해 `subscription_entitlements`를 실제 구매 결과로
  갱신하는 작업. 현재는 활성 entitlement를 발급하거나 UI에서 Plus를 구매할 수 없다.
